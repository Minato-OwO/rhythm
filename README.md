# FOUR FLOW

A-Frame 1.7.0で作る4レーン（4K）のVR対応音ゲーの土台。
キーボードと左右のVRコントローラーで同じ譜面・判定ロジックを使います。
KBモードもVRと共通の3D画面・スコアHUD・判定表示を使います。
通常画面は表示領域の大きさと `devicePixelRatio` に合わせて実ピクセル解像度で描画します。モニター移動・表示倍率変更・サイズ変更・フォーカス復帰時にも更新し、Canvasの解像度上限は設けません。VRの描画解像度はWebXR側に任せます。
KBの基準視点は高さ1.65m・後退距離30cmで、マウスドラッグやタッチで見回せます。
開始メニュー・一時停止・リザルト・設定・操作ボタンはすべて3D空間に表示します。
タイトルの「プレイする」で選曲画面へ進み、曲を選んで「この曲をプレイ」を押すと演奏を開始します。
一時停止すると専用のポーズ画面を表示します。「再開」は続きから、「リトライ」は同じ曲を最初から開始します。「退出」は演奏を終了して選曲画面へ戻り、途中のスコア・コンボをリセットします。
選曲画面から設定を開いた場合は、「戻る」で選曲画面へ戻ります。ポーズ画面もKB・VR共通の3Dパネルです。
曲は`songs/曲フォルダ/`ごとに音声ファイルと`chart.json`を保存し、3Dの選曲画面から切り替えます。
同じ曲の複数難易度は`chart_Easy.json`・`chart_Hard.json`の形式でまとめられます。選曲画面の中央右に難易度選択と譜面の詳細パネルを表示します。
選曲画面では設定した中央メニューの位置を2枚全体の中心として、曲一覧を左、詳細パネルを右に配置します。間隔は8cmで、2枚は同じ平面・角度に揃えます。前後距離・高さ・全体の移動設定も共通で反映します。
右の詳細パネルは中央パネルと平行な向きに配置します。タイトル・選曲・設定・ポーズ・リザルト、設定タブやページの切替には短いフェードを使います。
フェードはマテリアルの透明度だけを更新し、位置は動かしません。画面内容が切り替わる瞬間にだけ画像を描き直し、切替中のボタン操作を抑止します。
画面を切り替えるときは旧画面のフェードアウトを完了してから配置・内容を更新し、新しいパネルの準備が揃ってから同時にフェードインします。選曲画面への配置変更が見えた状態で行われることを防ぎます。
選曲中の曲・難易度・ページ変更ではパネルを消さず、表示したまま内容を更新します。選曲画面の「タイトルに戻る」（S・Escape）は、ポーズ・リザルトのどちらから来た場合も演奏状態を終了してタイトルへ戻ります。
譜面JSONの`events`で、時刻や拍に合わせてレーン発光・色変更・画面フラッシュ・フェードを指定できます。
背景色・背景パルス・星・背景用GLBも譜面の時刻で切り替えられます。エディタで配置・調整できます。
レーン左側に曲名・BPM・ノーツ数・進行度、右側にスコア・精度・コンボ・判定数を配置します。
プレイ中の左右パネルは、視線・マウス・VRコントローラーのレーザーが向いている間だけ表示します。フォーカスが外れて220ms後から240msでフェードアウトし、再び向けると140msで表示します。パネルが消えていてもフォーカスでき、ポーズ・設定・リザルトでは通常表示に戻ります。
「全部まとめて」の初期値は左右0m・上下0m・前後＋1.24m（手前）・左右の角度55度です。
左右パネルの基準距離は1.35mで、左右は内向き55度に配置します。
中央メニューの初期値は左右0m・高さ1.57m・距離2.10m・角度0度です。
3D設定画面の「パネル配置」タブで、左・右・中央それぞれの左右位置・高さ・前後距離・角度を調整できます。
角度は−85〜＋85度の範囲で1度刻みに調整でき、配置と一緒に自動保存します。
「全部まとめて」では、個別に調整した位置関係を保ったまま全パネルを左右・上下・前後に移動できます。
同じ画面の「左右の角度」で、左右パネルを対称の角度にまとめて揃えられます。正は内向き、負は外向きで、−85〜＋85度を1度刻みで調整・保存します。
全体の前後移動は−3m（奥）〜＋3m（手前）まで、0.01m刻みで調整できます。
「全体の調整をリセット」は全体の移動量と左右の角度を上記の初期値へ戻し、各パネルの個別位置は保持します。
保存済みの配置がある場合は保存値を使います。新しい初期配置をすべて反映するには「すべてリセット」またはPキーを使用します。
左右の位置・角度はすぐ反映し、中央の位置・角度は設定画面を「戻る」で閉じたときに反映します。
配置は自動保存され、パネル単位・全パネルのリセットも可能です。Pキーでも全配置を初期値へ戻せます。
中央のメニューはプレイ中に閉じ、レーンを空けます。カウントダウンと判定はレーン上に表示します。
レーンはタイトル・選曲などのゲーム開始前には表示せず、開始カウントダウンから表示します。ポーズ中は表示を保ち、リザルト・退出時に非表示へ戻ります。エディタの3Dプレビューでは停止中も表示します。
3Dパネルの画像は内容が変わったときだけ更新し、同じフレームの画像転送を1枚までに分散します。
進行バーとキー点灯は3Dオブジェクトとして毎フレーム動かし、画像の再転送はしません。
レーン1の左外側には残り時間バーを表示します。開始時は満タンで、手前の端を固定したまま奥の先端が手前へ縮み、曲の終了で空になります。レーン4の右外側にはスコア連動のノルマゲージを表示し、600k・900kの目印を付けています。ゲージはレーンの位置・傾き・VRの正面合わせに追従し、プレイ中とポーズ中に表示します。
「設定 → ゲージ」では、左の残り時間バーと右のノルマゲージの長さをそれぞれ0.1〜50.0m（0.1m刻み）で調整できます。初期値は両方15.0mです。変更は即時反映・自動保存し、手前の端・現在の割合・レーン本体への密着を保ちます。600k・900kの目印と文字も追従します。「ゲージの長さをリセット」で初期値に戻せます。
ノルマは600,000点でクリア、900,000点で上位クリアです。ゲージは未達時が赤、クリアで緑、上位クリアで金色に変わります。上位クリア時は選曲画面の自己ベストスコアとリザルトのランク・スコアも金色になります。リザルトにはクリア状態を表示し、従来の精度によるランク文字は維持します。オートプレイはノルマも表示しますが自己ベストには保存しません。
動的UI画像のミップマップ生成を無効にし、ノーツ描画は表示範囲の譜面だけを走査します。
パネルへの視線・マウス・VRレーザーは矩形との交点を直接計算し、判定結果を再利用します。ノーツの描画用オブジェクトは選曲中に最大128個まで事前に用意し、不足時は表示数を制限せず追加します。入力判定では終了済みのノーツを先頭から走査し直しません。
スコア・精度・コンボ・判定数・進行時間・判定文字は、起動時に作る共有の文字画像を使い回します。
これらの更新ではパネル画像を再描画せず、小さい文字用バッファだけを変更します。
ノーツと進行表示は、開始・再開時に音声時刻へ同期した表示時計を使います。
再生中はブラウザーの描画フレーム時刻（KBはrAF、VRはXR）から位置を直接計算し、毎フレーム音声時刻へ追従させる速度補正は行いません。
一時停止中は止め、再開時・音声の中断復帰時に同期し直します。ヒット・MISS判定と音源再生は音声時計を使用します。
ゲーム本体とエディタは共通の表示時計を使い、音声の停止・復帰が描画フレーム間に完了した場合も `statechange` を記録して再同期します。フォーカス復帰、250msを超える描画の中断、大きい時計差も再同期の対象です。ゲーム開始・再開処理中のフォーカス喪失による停止要求も保持し、復帰後は手動で再開します。エディタの停止位置には表示時計ではなく音声の実時刻を保存します。
ノーツは奥から手前へ進み、VRでは台の判定面をコントローラー先端で叩きます。
ヒット時は `assets/hit_se.mp3` を再生します。KB・VR・オートプレイ共通で、TAPとLNの始点で1回鳴り、MISS・空打ち・LN終点では鳴りません。LN保持中は `assets/LNLN.mp3` をループ再生し、離す・保持完了・ポーズ・退出で止めます。複数LNの同時保持でもループは1本を共有します。「設定 → プレイ設定」の「曲の音量」と「ヒットSEの音量」をそれぞれ0〜100%で独立して調整・自動保存できます（初期値は両方60%）。SEの音量は通常ヒットとLNループに共通です。両方のSEはゲーム開始前に読み込み・デコードし、再利用します。
通常ヒットの素材は差し替え後の `hit.mp3` を `assets/hit_se.mp3` として保存しています。通常ヒットとLN音の聴感上の音量差は再生時に補正します。10秒反復のラウドネス実測が通常ヒット−26.55 LUFS・LN−13.05 LUFSのため、LN側に−13.50dBを適用しています。音声ファイルの再圧縮は行いません。
曲に埋もれないよう、通常ヒットとLN保持音の共通ゲインを＋12dBにしています。保存済みのSE音量にも反映し、0%はミュートのままです。通常ヒットとLN保持音の音量バランスを保って増幅します。
3D設定画面の「レーン演出」タブで、エフェクト全体・入力時のレーン発光・ヒット時の波紋・火花を個別にON/OFFできます。
強さは0〜100%、表示時間は100〜800msで調整・自動保存し、KBとVRで同じ演出を使用します。
「演出を試す」で4レーンの演出を確認できます。初期値はすべてON、強さ60%、表示時間280msです。
演出は生成済みの形状を使い回し、火花は最大72個を1つのInstancedMeshで描画します。

## 起動

Node.js 18以上を使用します。追加パッケージのインストールは不要です。

```sh
npm start
```

ブラウザーで http://localhost:5173 を開きます。
最初のA-Frame読み込みにはインターネット接続が必要です。
初回起動時にデモの音声を生成し、`songs/neon-circuit/audio.wav`へ保存します。
曲一覧はサーバーが`songs`直下の曲フォルダから自動取得します。

### Renderへのデプロイ

Web ServiceのRoot Directoryはプロジェクト直下、Build Commandは `npm install`、Start Commandは `npm start` に設定します。ゲーム・エディタともルートのサーバーで配信するため、`editor` をRoot Directoryにする必要はありません。

Renderでは `0.0.0.0` と環境変数 `PORT` のポートで自動的に待ち受けます。`RENDER=true` で `PORT` が未指定の場合は10000を使います。通常のローカル起動は `127.0.0.1:5173` です。他の環境でも `PORT` が指定されていれば `0.0.0.0:PORT` を使い、CLIの `--host`・`--port` があればそちらを優先します。

Renderの公開HTTPSはRender側が処理するため、通常は `--cert`・`--key` を指定せずに起動します。ローカルでのHTTP・証明書を使ったHTTPS起動は引き続き利用できます。
仕様は[Renderのポート設定](https://render.com/docs/web-services#port-binding)を参照してください。

長押しのキーリピートは判定しません。同時押しに対応します。
VRでは左右の手とも全レーンを叩けます。再判定するには一度手を上げる必要があります。

「設定 → プレイ設定 → オートプレイ」をONにすると、次の開始・リトライからTAPとLNを自動で演奏します。初期値はOFFで、設定は自動保存します。KB・VRのどちらでも使え、選曲画面の開始ボタンは「オートプレイで再生」に変わります。
判定はすべてPERFECT+（ずれ0ms）です。LNは終点100ms前まで自動保持し、レーンの点灯・ヒット演出も通常どおり動きます。入力オフセットや手動入力では判定を変えず、SV・speed・個別SVはそのまま表示します。一時停止・再開・退出にも対応します。
オート中はHUD・ポーズ・リザルトにAUTO PLAYを表示し、スコア・精度・コンボを自己ベストへ保存しません。演奏途中に設定を変更してもそのプレイのモードは変わらず、次の開始・リトライから反映します。

## VRで開く

WebXRのimmersive-vrとlocal-floor、位置追跡付きの左右コントローラーを使用します。
PCに接続したHMDの場合はlocalhostで開けます。
単体ヘッドセットからLAN内のPCへ接続する場合は、ヘッドセットが信頼する証明書を使ったHTTPSで提供してください。

```sh
npm start -- --host 0.0.0.0 --cert ./certs/cert.pem --key ./certs/key.pem
```

ヘッドセットの対応ブラウザーで `https://PCのIPアドレス:5173` を開き、
「VRでプレイ」を押します。証明書は接続先のホスト名またはIPに有効なものを使用します。
`certs/` 配下のファイルは開発サーバーから配信しません。

入室後は正面へレーンを配置します。必要ならスティック押し込みで合わせ直します。
VR視点は実機の床基準の高さを使います。追跡未取得時は1.65mを使用し、
床付近の高さが返る場合はカメラと左右コントローラーを共通のrigで補正します。
この基準高は `src/config.js` の `vrEyeHeight` で変更できます。
視点と両コントローラーは正面方向から水平に30cm後退させます。
距離は `src/config.js` の `vrBackOffset`（メートル）で変更できます。
位置合わせのたびに後退が重なることはありません。
トリガーでカウントダウンを開始します。HUD・開始・一時停止・再プレイはHMD内で利用できます。
VR退出・タブ非表示・XRセッションの非表示で一時停止します。

## 判定

- PERFECT+: ±20 ms / PERFECT: ±45 ms / GREAT: ±90 ms / GOOD: ±150 ms / 以降MISS。KB・VRとLN始点に共通です。
- スコアは「基本点（1,000,000点満点）＋PERFECT+の数×1点」。基本点は判定重みの合計÷総ノーツ数×1,000,000を四捨五入します。理論値は1,000,000＋総ノーツ数です。ノルマ判定は追加点を含むスコアを使い、600,000点でクリア、900,000点で上位クリアです。
- 精度は「基本精度％ ＋ PERFECT+数÷総ノーツ数×10％」の形で表示します（例：100.00% + 7.50%）。追加分は最大10.00%です。基本精度のPERFECT+ / PERFECT / GREAT / GOOD / MISSの重みは1 / 1 / 0.7 / 0.4 / 0です。LNは完了時に始点の判定で1回だけ加点・集計します。
- 空打ちのペナルティはありません。MISSでコンボが切れます。
- 正の入力オフセットは、入力時刻をその分だけ過去へ補正します。
- 音声オフセットは音源だけをずらします。＋で再生を遅らせ、−で早めます（初期値0 ms、−500〜＋500 ms、5 ms刻み）。入力オフセットと独立しており、ノーツの表示・判定時刻は変えません。
- 一時停止中に音声オフセットを変更すると、再開時に補正した音源位置から再生します。音源がない曲の合成音にも反映します。
- スクロール速度は0.6〜10.0倍（0.1刻み）で調整できます。見た目の到達時間だけを変え、楽曲と判定時刻は変えません。

VR入力はXRFrameのgripSpaceのポーズから先端位置を計算します。
連続フレーム間の判定面通過を補間し、その位置・時刻・下向き速度を使って判定します。
レーンの隙間や奥行き範囲外、遅い動き、上向きの動きでは判定しません。
追跡喪失、フレーム間隔の空き、極端な位置飛びでは前回のサンプルを破棄します。
左右は独立して判定し、対応機器ではヒット時に短く振動します。

判定面の高さ・最低振り下ろし速度・音量・ノーツ速度・入力オフセット・音声オフセットは設定から変更できます。
設定はブラウザー内に保存します。判定窓やレーン幅・奥行きの許容範囲は `src/config.js` で変更します。

設定の「レーン配置」から、レーンの前後位置・傾き・判定面の高さを調整できます。
「黒い下地の透明度」ではレーン下の黒いカバーを0〜100%で調整できます。0%は不透明、100%は透明で、初期値は0%です。変更はすぐに反映・自動保存され、「レーン配置をリセット」で元に戻ります。
前後位置は初期位置から−3〜＋3m（1cm刻み、＋で手前）、傾きは−30〜＋75°（1°刻み、＋で奥側を持ち上げる）です。初期値は前後0m・傾き0°です。
傾きは判定ラインを軸に変わるため、角度の変更だけで判定ラインの高さや前後位置は変わりません。
ノーツ・LN・レーン演出・VRの振り判定が同じ配置に追従します。楽曲と判定の時刻は変わりません。
KB・VRで設定を共有し、正面合わせやモード切替後も保持します。「レーン配置をリセット」で前後・傾き・高さを初期値に戻せます。

## 自分の譜面・音源

同じ曲の難易度別ファイルは、曲フォルダ直下に`chart_[難易度].json`という名前で配置します。
たとえば次の構成では、選曲一覧には曲を1件表示し、右の詳細パネルでEasyとHardを切り替えます。

```text
songs/
  my-song/
    audio.mp3
    chart_Easy.json
    chart_Hard.json
```

各JSONは従来の`chart.json`と同じ書式の、独立した完全な譜面です。`title`・`artist`を各難易度で共通にし、`audio`は両方とも`"./audio.mp3"`を指定できます。
難易度名はファイル名の`chart_`と`.json`の間から取得します。任意の数値`level`を加えると難易度ボタンに`Lv.`を表示し、数値順に並べます。
従来の`chart.json`も読み込めます。その難易度名はJSONの`difficulty`、OSUの難易度名、`Normal`の順で決めます。
`chart.json`と難易度別JSONを両方置いた場合は、すべてを難易度として表示します。ファイルを追加・編集したら選曲画面の「一覧を更新」で反映します。
OSUから別フォルダへ変換した既存譜面も、有効な同一のBeatmapSetIDを持つ`chart.json`同士は1曲の難易度としてまとめます。

難易度ごとに「点滅注意」を出す場合は、その譜面JSONのルートへ次の項目を追加します（既存の曲情報・ノーツはそのまま残します）。

```json
{
  "flashWarning": true,
  "flashWarningText": "ストロボなどの点滅演出があります。"
}
```

`flashWarning` は省略または `false` で非表示、`true` で表示します。たとえば `chart_Easy.json` は `false`、`chart_Hard.json` は `true` にできます。
`flashWarningText` は任意の補足文です。省略・空欄の場合は「点滅演出が含まれます。」を表示します。
難易度ボタンには「点滅注意」の印を表示し、選択中の難易度では詳細パネルの見出しとプレイボタンの上にも表示します。長い補足文は表示幅に合わせて省略します。
エディタの曲情報でも、チェックボックスと補足入力から設定できます。演出の内容による自動判定は行わず、難易度ごとの指定を使います。JSONを変更した場合は「一覧を更新」で未選択の難易度ボタンにも反映します。

右の詳細パネルには次を表示します。

- 難易度選択（5つ以上の場合はページ切替）。
- 曲の長さ、平均密度、ピーク密度、時間ごとの密度グラフ。
- 各レーンのTAP数・LN数・合計、および総ノーツ数と総LN数。
- 選択中の難易度の自己ベストスコア・精度・最大コンボ。

自己ベストは曲を最後までプレイした時に、3項目それぞれの最高値を更新します。リトライ・途中退出では更新しません。
精度の自己ベストは基本精度と追加分の合計で比較し、そのプレイの内訳をセットで保存・表示します。
記録は難易度ごとにこのブラウザーへ保存し、再読み込み後も表示します（KB・VR共通）。未プレイの難易度は「—」と表示します。
基本100万点＋PERFECT+方式の自己ベストは `fourflow.personal-bests.v3` に保存します。以前のv1記録と、基本10万点＋PERFECT+方式のv2記録はブラウザー内に残し、新方式の記録とは混ぜません。旧スコアからPERFECT+加点を正確に分離できないため、自動換算は行いません。

総ノーツ数はTAP＋LNで、LNは始点を1ノーツとして数えます。LN終点・保持時間・SVは密度の計算に加えません。
平均密度は総ノーツ数÷曲の長さ（秒）、ピーク密度は1秒区間ごとの最大ノーツ数です。
20分を超える譜面では集計区間を広げ、区間内のノーツ数÷区間秒数を表示します。グラフはTAPとLNを色分けし、表示を縮めても局所的なピークを残します。
曲の長さは音源のメタデータから再生せずに取得します。取得できない場合や音源のない曲では「譜面長」と明記して譜面の長さを使います。
集計とグラフの更新は選曲・難易度変更時に行い、演奏中は詳細パネルを非表示にします。

曲ごとにフォルダを作り、音声と譜面を一緒に保管します。

```text
songs/
  neon-circuit/
    chart.json
    audio.wav
  my-song/
    chart.json
    audio.ogg
```

`examples/song/chart.json`を自分の曲フォルダへコピーし、音声を追加してください。
登録用の一覧ファイルやJavaScriptの編集は不要です。追加・編集後に「選曲 → 一覧を更新」を押して曲を選び直します。
選択した曲は次回起動時にも使用します。読み込みに失敗した場合は現在の曲を保持します。

```json
{
  "version": 1,
  "title": "My Song",
  "artist": "Artist",
  "bpm": 120,
  "audio": "./audio.ogg",
  "offsetSeconds": 0,
  "durationSeconds": 8,
  "notes": [
    { "beat": 0, "lane": 0 },
    { "beat": 1, "lane": 1 },
    { "beat": 2, "lane": 2 },
    { "beat": 3, "lane": 3 },
    { "beat": 4, "lane": 0 },
    { "beat": 4, "lane": 3 }
  ],
  "events": [
    { "beat": 0, "type": "lanePulse", "durationSeconds": 0.5, "intensity": 0.7 },
    { "beat": 2, "type": "laneColor", "lanes": [0, 3], "color": "#ab78ff", "durationSeconds": 0.5 },
    { "timeSeconds": 2, "type": "screenFlash", "color": "#ffffff", "durationSeconds": 0.4, "intensity": 0.2 },
    { "beat": 8, "type": "screenFade", "color": "#000000", "durationSeconds": 2, "intensity": 0.6, "fadeInSeconds": 0.5, "fadeOutSeconds": 0.5 }
  ]
}
```

`audio`は譜面JSONからの相対パスです。同じフォルダなら`./audio.ogg`や`./music.mp3`と指定します。
WAV・OGG・MP3・M4Aなど、使用ブラウザーがデコードできる形式を使えます。
音源の0秒が楽曲時刻0で、開始前のカウントダウンは含みません。
従来の`audioUrl`も読み込めますが、ファイルから読み込む場合の基準は同じく譜面JSONになります。

`lane`は左から0〜3、`beat`は0始まりです。同時押しは同じbeatに別laneのノーツを置きます。
beat指定の時刻は`beat × 60 / bpm + offsetSeconds`です。ノーツ・演出の両方に適用します。
`timeSeconds`がある場合はbeatとoffsetSecondsを使用せず、その秒数を音源の先頭から直接指定します。
`durationSeconds`は曲の終了時刻で、最後のノーツから1秒以上後、かつ全演出の終了以降に指定します。
省略時は最後のノーツ・演出から自動計算します。長い音源の末尾まで再生する場合は音源の長さを指定してください。
VR用譜面は同時ノーツ数を2つ以内にすると両手で演奏できます。

### 時刻指定の演出

`events`は省略できます。各イベントの時刻は`beat`または`timeSeconds`で指定します。

| type | 内容 | 主な指定 |
| --- | --- | --- |
| lanePulse | レーンを一度発光させ、指定時間で減衰 | lanes、color、intensity、durationSeconds |
| laneColor | レーン・ノーツ・ヒット演出を指定色へ移行 | lanes、color、durationSeconds |
| screenFlash | 視界全体を一瞬着色し、指定時間で減衰 | color、intensity、durationSeconds |
| screenFade | 視界を指定色へフェードし、保持してから元に戻す | color、intensity、durationSeconds、fadeInSeconds、fadeOutSeconds |
| backgroundStage | 標準の床グリッド・アーチをフェード・着色し、変更後も保持 | target、opacity、color、durationSeconds、easing |
| backgroundColor | 背景色・霧の色を変更し、変更後も保持 | color、durationSeconds |
| backgroundPulse | 背景・標準の床やアーチ・GLBを一度発光させて減衰 | color、intensity、durationSeconds |
| backgroundStars | 固定384個の星を表示 | color、intensity、size、rotationSpeed、durationSeconds、fadeInSeconds、fadeOutSeconds |
| backgroundGLB | GLBを表示・切り替え・非表示 | src、position、rotation、scale、fitSize、rotationSpeed、durationSeconds、fadeInSeconds、fadeOutSeconds、animation |
| backgroundScene | JSで作る3D背景シーンを表示・切り替え | src、position、rotation、scale、rotationSpeed、animationSpeed、durationSeconds、fadeInSeconds、fadeOutSeconds |

色は`#rrggbb`形式、強さ`intensity`は0〜1です。
`lanes`は対象レーンの配列で、省略すると全レーンです。1レーンだけなら`"lane": 0`とも書けます。
`lanePulse`の色を省略すると、その時点のレーン色を使います。重なった発光は最も強いものを描画します。
レーン演出は設定の「レーンエフェクト」と「エフェクトの強さ」に従います。
`laneColor`の変更は移行後も保持し、次の色変更・リトライ・選曲で更新します。時間0なら即時変更です。
同じレーンに色変更が重なる場合は、あとから始まる変更が優先されます。

`screenFlash`は標準で白・強さ0.25・0.4秒、`screenFade`は黒・強さ0.6・2秒です。
`screenFade`の`fadeInSeconds`と`fadeOutSeconds`は演出全体の長さに含まれ、残りが保持時間です。
省略時はそれぞれ最大0.25秒です。両方の合計は`durationSeconds`以下にしてください。
画面演出も3D空間に描画し、KBとVRで共通です。カメラや判定面は動かしません。

演出は曲の時刻から描画し、一時停止中は経過しません。
一時停止メニューを開いている間は画面の着色を隠し、再開すると同じ進行位置から表示します。
再プレイ・曲変更時には前の曲の演出をリセットします。
色・形状・演出データは読み込み時に用意し、再生中の画像生成やタイマー登録は行いません。

### 背景・GLB

背景GLBは音声・譜面と同じ曲フォルダへ配置します。サブフォルダも使用できます。
テクスチャなどを内包したGLB形式を使用してください。
`src`は譜面JSONからの相対パスです。

```json
[
  { "beat": 0, "type": "backgroundColor", "color": "#060b20", "durationSeconds": 1 },
  { "beat": 0, "type": "backgroundStars", "color": "#b9d9ff", "intensity": 0.5, "size": 0.035, "rotationSpeed": [0, 1, 0], "durationSeconds": 16 },
  { "beat": 16, "type": "backgroundPulse", "color": "#c881ff", "intensity": 0.5, "durationSeconds": 0.8 },
  {
    "beat": 8,
    "type": "backgroundGLB",
    "src": "./night_sky_visible_spectrum_monochromatic.glb",
    "durationSeconds": 40,
    "intensity": 1,
    "color": "#ffffff",
    "position": [0, 1.65, -20],
    "rotation": [0, 0, 0],
    "scale": [1, 1, 1],
    "fitSize": 100,
    "rotationSpeed": [0, 1.5, 0],
    "fadeInSeconds": 1.2,
    "fadeOutSeconds": 1.5,
    "animation": "none",
    "animationSpeed": 1,
    "loop": true,
    "hideDefault": true
  }
]
```

上の配列は`events`内に置くイベントの例です。実際のGLBファイルを同じ曲フォルダに配置してください。
サンプル曲には追加済みの夜空GLBを使うイベントを設定しています。128BPMの8拍目（3.75秒）から40秒間表示します。

- `position`：レーン中央の床を基準にしたメートル。右がX正、上がY正、奥がZ負です。既定値は`[0, 0, -15]`。
- `rotation`：XYZの角度（度）。既定値は`[0, 0, 0]`。
- `scale`：XYZの倍率。すべて正の値で、既定値は`[1, 1, 1]`。
- `fitSize`：モデルの最長辺を揃える長さ（m）。既定値20。0ならモデル本来の寸法を使います。モデルの中心をpositionへ合わせ、その後scaleを適用します。
- `rotationSpeed`：XYZの回転速度（度/秒）。既定値`[0, 3, 0]`。
- `intensity`：GLBの不透明度。既定値1。`color`で色を乗算します。
- `animation`：`auto`で最初のアニメーション、`none`で停止、名前で指定したアニメーションを選びます。既定値auto。
- `animationSpeed`：アニメーションの速度。既定値1。0で停止。
- `loop`：アニメーションを繰り返すか。既定値true。
- `hideDefault`：表示中は標準の床グリッド・アーチを隠すか。既定値true。レーンや情報パネルはそのまま表示します。

GLB・星のフェード時間はそれぞれ既定で最大0.5秒、表示時間に含まれます。
モデルを切り替えるには別の`backgroundGLB`イベントを配置します。同時に表示するGLBは1つで、後から開始したイベントを優先します。
`"src": null`でその区間のGLBを隠します。イベント終了後は、前の表示イベントが継続中なら戻ります。
背景色は変更後も保持し、次の変更・リトライ・選曲で更新します。移行時間0も使用できます。
星は後から始まるイベントを優先し、背景パルスは重ねて加算します。

標準ステージは `backgroundStage` で調整します。エディタでは演出の種類から「標準ステージ」を選び、「＋演出」で配置します。
対象 `target` は `all`（床・アーチ全部）、`grid`（床グリッド）、`arches`（アーチ）です。
`opacity` が変更後の表示量で、0は非表示、1は元の表示量、0.5は半透明です。`durationSeconds` が変化にかける時間で、0なら即時切替します。
`easing` は `linear`（一定の速さ、既定値）または `smoothstep`（なめらか）です。任意の `color` で元のデザインへ着色し、省略・nullなら元の色へ戻します。
次の例では8秒目から2秒で消し、16秒目から2秒で再表示します。値は変化後も保持し、同じ対象に後から始まるイベントを優先します。変化の途中で別のイベントが始まる場合も、その時点の表示量・色から移行します。

```json
[
  { "timeSeconds": 8, "type": "backgroundStage", "target": "all", "opacity": 0, "durationSeconds": 2, "easing": "smoothstep" },
  { "timeSeconds": 16, "type": "backgroundStage", "target": "all", "opacity": 1, "durationSeconds": 2, "easing": "smoothstep" }
]
```

標準ステージ演出を指定した対象は、開始以降、背景GLB・JSの `hideDefault` による自動非表示より優先されます。最初の演出は直前の自動表示状態から移行するので、非表示中からのフェードインも設定できます。
ノーツ・レーン・操作パネルには作用しません。ゲームと3Dプレビューで同じ処理を使い、ポーズ・任意位置へのシーク・リトライに追従します。
床・アーチを別々に再表示するサンプルは `examples/default-stage/chart.json` にあります。リトライ・退出・曲変更では標準ステージを初期状態へ戻します。

モデルの中心・サイズは読み込み時に算出します。GLBは曲の開始・選択前に読み込み、テクスチャとシェーダーも準備します。
同じGLBを複数の時刻で使用しても、読み込んだデータを使い回します。曲変更で不要になったモデルは破棄します。
背景用の描画には照明不要のマテリアルを使い、発光テクスチャがある場合はその画像を優先します。
回転・アニメーション・フェードは楽曲時刻から計算し、一時停止やエディタのシークに追従します。

## 譜面エディタ

`songs/neon-circuit/dist/background.js` は氷と時計の背景シーン用モジュールです。Neon Circuitの譜面は開始時から46秒間このシーンを表示する設定になっています。
`backgroundScene` の `src` は譜面JSONを基準にしたJSの相対パスです。任意の拍・秒数にイベントを置けます。GLBと重なる場合は後から開始した背景を優先し、終了後は継続中の以前の背景へ戻ります。
時計・粒子・フェードは楽曲の絶対時刻に同期します。曲変更・退出で不要な背景の描画資源を解放します。
背景モジュールは `createBackground({ THREE, scene, renderer })` を公開し、`{ object3D, update(time), dispose() }` を返します。更新時刻はイベント開始からの秒数です。
戻り値に `preserveMaterialState: true` を付けると、各マテリアルの元の `transparent`・`depthWrite` と描画順を保ち、演出のフェード中だけ半透明描画に切り替えます。フェード中の `alphaToCoverage` は無効にし、通常・フェードのシェーダーを読み込み時に準備します。Chronomiaの背景はこの設定を使用し、文字盤と床は不透明、文字盤画像の抜きは透過マスクとして描画します。時計の針と中心の宝石は画像のアルファを使う半透明描画です。粒子の動きはGPUで計算します。結晶・粒子の数、画像・反射の解像度、照明は変更していません。

Chronomiaの氷山は元の不透明な材質を使い、青色を少し淡くしています。結合描画による軽量化は維持しています。
エディタでは「ゲームの曲」から開き、「背景シーン(JS)」でパス・配置・長さ・速度を編集できます。フォルダ保存・JSON保存ではJS素材は自動コピーしないため、別曲への移植時は `dist` 全体をコピーしてください。
詳しい使用例は `songs/neon-circuit/dist/README.md` を参照してください。

ゲームのサーバーを起動し、`http://localhost:5173/editor/`を開きます。
ゲームと同じサーバーからエディタのソースを配信するため、エディタのビルドは不要です。
`editor`にあったエディタのタイムライン・プロパティ・フォルダ読み込みの構成を、このゲーム用に改修しています。

- 「曲フォルダを開く」、フォルダのドロップ、または「ゲームの曲」一覧から曲を開きます。
- ノーツはD/F/J/Kの4レーン。タイムラインのダブルクリックやD/F/J/Kキーで再生位置へ配置できます。
- レーン発光・色変更・画面フラッシュ・フェードを追加し、開始拍・秒数・長さ・色・強さ・対象レーンを編集します。
- 背景色・パルス・星・背景GLBも追加できます。「GLBを追加」で素材を読み込み、プロパティで位置・角度・大きさ・回転速度・フェード・動作を調整します。
- プレビューはゲーム本体と同じ3Dレーン・ノーツ・演出処理を使用します。停止中のシークでも演出を確認できます。
- 「フォルダへ保存」は`chart.json`と音声・GLB素材を保存します。「JSON保存」は`chart.json`をダウンロードします。

詳細な操作とViteでの開発方法は`editor/README.md`を参照してください。

タップとLN（ロングノーツ）に対応しています。LNは始点を叩き、終点100ms前まで維持します。
KBは同じキーを押し続け、VRは始点を叩いた手の先端を同じレーンの判定面付近に留めます。
LNは1本を1ノーツとして集計します。途中で離すとMISS、完走時は始点の精度を採用します。
終点で離すタイミングの判定はありません。終点100ms前まで維持できれば、その時点で始点の精度のまま成功になります。その後は押し続けても離しても構いません。
100msより短いLNは始点時刻以降に完了します。LNの胴は始点と同じ幅で、通常時もほぼ不透明、保持中は不透明に描画します。
VR追跡の途切れには120ms、ポーズからの復帰には400msの猶予があります。
タブ非表示・ウィンドウのフォーカス喪失で一時停止し、停止中はLNの判定も止まります。
依頼に合わせてコードを作成した状態で、実行・コード確認・画面確認・実機確認は行っていません。

## OSZ・OSUの変換とSV・LN

エディタの「OSZ / OSU読込」から読み込みます。
OSZをそのまま選ぶか、OSUと音声をまとめて選択してください。
展開済みのフォルダは「曲フォルダを開く」またはドロップで読み込めます。
複数の4K譜面がある場合は難易度を選びます。
読み込んだ後は「フォルダへ保存」で、chart.jsonと音声を保存します。
OSUからの読み込みは元ファイルを保持し、保存先を改めて選びます。

追加インストール不要のコマンド版もあります。プロジェクト直下で実行します。

```powershell
npm run convert:osz -- "C:\path\to\beatmap.osz"
npm run convert:osz -- "C:\path\to\beatmap-folder" --list
npm run convert:osz -- "C:\path\to\beatmap-folder" --difficulty "Difficulty"
```

今回のフォルダを変換する例：

```powershell
npm run convert:osz -- "songs/1822673 Daniel Bedingfield - Gotta Get Thru This (Jauz RetroFuture Remix) (Nightcore Mix)" --difficulty "Getting Thru These SVs"
```

既定の出力先はsongsです。難易度ごとにosu-ID-難易度名のフォルダを作り、chart.jsonと音声を保存します。
--difficultyを省略すると全4K譜面、--outputで出力先を指定、--forceで既存の変換先を上書きします。
元のOSZ・OSU・音声は書き換えません。変換後はゲーム内の曲一覧を更新して選択します。

- 対象はosu!maniaのMode:3 / CircleSize:4。タップとLNの絶対時刻を保持します。
- 緑線のSVと赤線のBPM変更を合成してscrollVelocitiesへ変換します。緑線の倍率は0.01〜10に収めます。
- 曲内で最も長く使われるBPMを基準にします。ピクセル単位の表示距離は本ゲームのノーツ速度設定で調整してください。
- 音声は変換せずコピーします。DT・HTなどプレイ時のModや、カスタムヒットサウンドは適用しません。
- 画像・動画・ストーリーボードの演出は変換しません。元の曲情報・譜面作者・タイミングポイントはJSONのosu内に保持します。
- コマンド版の終了時刻は最後のノーツ・LN終点から2秒後が基本です。エディタ読み込みでは音源の長さまで延長します。
- ZIP64・暗号化ZIPには対応していません。ファイル名を読めないOSZは展開済みフォルダで読み込めます。

LNはnotesのendTimeSecondsまたはendBeatで指定します。省略するとタップです。
同じレーンでLNの途中に別のノーツ・LNを重ねることはできません。終点と次の始点を同じ時刻に置くことはできます。

```json
{
  "notes": [
    { "timeSeconds": 2, "endTimeSeconds": 6, "lane": 0, "scrollMultiplier": 1.5 },
    { "beat": 16, "endBeat": 20, "lane": 3, "scrollMultiplier": 0.75 }
  ],
  "scrollVelocities": [
    { "timeSeconds": 0, "multiplier": 1 },
    { "timeSeconds": 3, "multiplier": 0.5 },
    { "timeSeconds": 4, "multiplier": 2 },
    { "timeSeconds": 5, "multiplier": 1 }
  ]
}
```

上記は譜面JSON内の項目です。通常の曲情報と組み合わせて使用します。
SVは開始時刻をtimeSecondsまたはbeatで指定し、次の同じタイプのSVまで有効です。
`type` は `scroll`（従来方式、既定値）または `speed`（現在の倍率でノーツ全体の間隔を変更）です。省略した既存譜面は従来どおり動作します。両タイプは独立して倍率を保持し、併用できます。
従来のscrollでは倍率1は通常、0は停止、負数は逆走。−1,000,000〜＋1,000,000の有限値を使えます。scroll・speedの固定倍率、範囲SVの開始倍率と終了倍率、個別SVで同じ上限を使います。
停止・逆走は自作JSON/エディタで設定でき、OSUの緑線は正の倍率として変換します。
scrollは速度変化の区間積分からノーツ位置を計算し、切り替え時の位置飛びやフレーム依存の累積誤差を防ぎます。
SVは見た目だけに作用し、音声・判定時刻・LNを維持する実時間は変えません。

speedは指定時刻の倍率を、判定線を基準にTAP・LN全体の表示距離へ掛けます。×2でノーツ間隔が一斉に2倍、×0.5で半分になります。未来のspeed設定は現在の間隔に影響せず、下記の例では8秒になるまで等倍、8秒ちょうどで2倍、10秒で0.5倍になります。

```json
"scrollVelocities": [
  { "timeSeconds": 8, "type": "speed", "multiplier": 2 },
  { "timeSeconds": 10, "type": "speed", "multiplier": 0.5 },
  { "timeSeconds": 12, "type": "speed", "multiplier": 1 }
]
```

speedの0はノーツを判定線上に集め、負数は前後を反転します。0の間は通常の接近時間内と保持中のLNを表示します。LNの始点・胴・終点と個別SVにも同じspeed倍率を掛け、保持中の始点は判定線上に残します。範囲でspeedを変化させる場合も、現在の倍率で全体の間隔を変えます。サンプルは `examples/sv-speed.json` です。

全体SVを一定の範囲で変化させる場合は、開始倍率 `multiplier` に加えて `endMultiplier` と長さを指定します。次は16拍目から4拍かけて−9から1へ滑らかに変化させる例です。

```json
{ "beat": 16, "multiplier": -9, "endMultiplier": 1, "durationBeats": 4, "easing": "smoothstep" }
```

長さは `durationBeats`（拍数）または `durationSeconds`（秒数）のどちらかで指定します。拍数は曲の基準BPMで秒に換算します。
`easing` は `linear`（一定の割合で変化、既定値）と `smoothstep`（始めと終わりがなめらか）です。
長さの終了後は終了倍率を保持し、途中で次のSVが始まった場合はそちらを優先します。長さ0では終了倍率へ即時切替します。終了倍率の省略時は開始倍率と同じになり、従来の固定倍率SVもそのまま読み込めます。
範囲の終点を固定倍率区間の始点として分離し、そこから次の固定SVまでは終了倍率を一定で保持します。次の固定SVへ向けた自動補間はせず、その開始時刻で即座に切り替えます。
`mode` は `constant`（固定倍率）または `range`（範囲変化）を指定できます。省略した従来データは範囲用フィールドの有無で判断します。固定倍率を明示した場合は範囲用の値が残っていても使いません。
エディタのタイムライン上部には、再生位置の倍率を `SV ×倍率 / SPEED ×倍率` と表示します。従来の範囲SVサンプルの9〜10秒は倍率2を保持し、10秒ちょうどで固定倍率0へ切り替わります。
scrollの範囲変化も速度を解析的に積分し、フレームごとの足し込みや細かい固定SVへの分割は行いません。負から正への折り返し位置もLNの表示範囲に含めます。
エディタでは「＋全体SV」で追加後、プロパティの「SVタイプ」でscroll・speedを、「倍率の変化」で固定倍率・範囲変化を選べます。両タイプとも「範囲で変化」から設定し、タイムラインの帯の両端でも長さを調整できます。従来の範囲SVサンプルは `examples/sv-range/chart.json` です。

各ノーツの `scrollMultiplier` で個別SVも指定できます。省略時は1、範囲は−1,000,000〜＋1,000,000の有限値です。
判定線からの表示距離は「scrollの積分距離差 × プレイヤーの速度設定 × 現在のspeed倍率 × 個別SV」で決まります。speedが1のときは従来と同じです。個別SVが2なら同じノーツの間隔が2倍、0.5なら半分になります。
個別SVの0は通常の接近時間から判定線上に固定し、負数は移動方向を反転します。LNは始点・胴・終点すべてへ同じ倍率を使います。
エディタではノーツの「個別SV倍率」と「＋全体SV」でそれぞれ設定し、3Dプレビューとゲーム本体に同じ計算を使います。
エディタの表示倍率とプレビューは、親画面の同じ再生時計を直接共有します。iframe側の時計の起点を足して時刻を外挿せず、固定SVの切替時刻を揃えます。譜面の更新待ちでは、古いSVを新しい再生状態で描画しません。
画面を開かない確認は `npm run test:preview`、speedの配置・保存・表示索引の確認は `node --test tests/speed-sv.test.mjs` で実行できます。
表示対象は倍率に応じた区間の索引から取得し、個別SVが混在しても毎フレームの全ノーツ走査を避けます。speedの範囲変化中も索引は作り直さず、表示対象を探す範囲を変更します。
変換したノーツ・SVは絶対秒で保持します。エディタの拍目盛・拍入力・メトロノームは曲情報の基準BPMを使います。
